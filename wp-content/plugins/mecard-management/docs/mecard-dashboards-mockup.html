Build notes — for the developer reading this

1. Where this lives

Custom WP admin page under MeCard Staff Backend (existing menu). New module Me\Analytics\Module registered alongside the editor modules in mecard-management.php. Data reads come directly from {$wpdb->prefix}mecard_events via prepared statements.

2. Profile-view source distinction

Both /t/{token} and /mecard-profile/{slug} fire profile_viewed. To split them in queries without adding a new event:

  • Add an entry_url_pattern field to the meta JSON on profile_viewed with value 't' or 'mecard-profile'. Detected server-side from the matched rewrite rule before the page renders.
  • Counted via JSON_EXTRACT(meta, '$.entry_url_pattern'). MySQL 5.7+ supports this; WAMP local is fine.

3. Segmentation logic (recommended)

Computed at query time, no new column needed. Pseudo-SQL:

SELECT
  user_id,
  CASE
    WHEN first_order_product_id IN (2044, 11160, 3189) THEN 'team_intent'
    WHEN profile_count = 1 THEN 'single'
    WHEN profile_count > 1 AND first_order_product_id NOT IN (2044, 11160, 3189) THEN 'team_converted'
  END AS segment
FROM (
  SELECT user_id,
    (SELECT product_id FROM ...first order...) AS first_order_product_id,
    COUNT(DISTINCT profile_id) AS profile_count
  FROM users LEFT JOIN profiles ...
) base;

Product IDs from wp-config.php: MECARD_BUNDLE_PRODUCT_ID = 2044, MECARD_CLASSIC_BUNDLE_PRODUCT_ID = 11160, MECARD_CLASSIC_CORP_PRODUCT_ID = 3189. Treat any of these as team-intent on first order.

4. Caching

Dashboard queries are aggregate scans across mecard_events. Wrap each widget's query in a 5-minute transient (set_transient('mecard_dash_kpi_signups', ..., 300)) — analytics doesn't need real-time. Bypass cache with ?nocache=1 for debugging.

5. Team-owner dashboard auth

Team owner = the user who owns the mecard-company record. Members = all mecard-profile CPTs with that company linked. The dashboard query scopes mecard_events by profile_id IN (...team profile ids...). Member never sees own data on this page — separate "my stats" page for that.

6. The "nudge" action

Sends a templated WP email to the underperforming team member: "Your card has had X views this month — here are 3 ways to share it." Logs team_nudge_sent as a new event so we can measure whether nudges actually drive subsequent shares.

7. Not in v1 dashboards (future)

  • Drill-down to individual session timelines
  • Cohort retention by acquisition channel
  • Geographic heatmap (vs. the simple country table)
  • Referral / share-token attribution (waits for the v2 referral spec)
  • Per-profile "stats" page for individual team members (separate spec)
